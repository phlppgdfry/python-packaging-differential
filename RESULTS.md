- **Release numbers above 2^64 - 2 are rejected.** Release segments are stored as u64; the error says so explicitly.
- **Leading or trailing whitespace around a version is rejected.** `Version::from_str` does not strip whitespace; packaging does (PEP 440 says it should be ignored). uv's callers trim input before parsing, so this only shows when the crate is called directly.
- **`===` compares parsed versions, not strings, and needs a valid version.** Documented in the code: 'This isn't standards-compliant, but it's consistent with the resolver'.
- **packaging keeps the original spelling of a specifier's version.** `str(SpecifierSet('==v1.0'))` is `==v1.0`; uv renders the parsed version `==1.0`. Same set.
- **An empty specifier or empty clause (`""`, `,`, a trailing comma) is rejected.** The PEP 440 grammar has no empty clause; packaging silently drops it.
- **A marker comparing a version key with something that is not a valid specifier evaluates to true.** The parser reports 'Expected PEP 440 version ... will be ignored' and drops the expression. packaging falls back to a string comparison (usually false) or raises.
- **Python version markers compare only the release part (epoch, pre, post, dev, local ignored).** Documented: 'uv truncates the candidate version to the major, minor, and patch components'. The marker algebra calls `only_release()` and has a `release_only` test.
- **`in` with a version key is a whitespace-separated list of versions, not a substring test.** PEP 508 defines `in` as Python string containment, which packaging follows ('3.1' in '3.12' is true). uv and poetry-core read the right side as a list of versions. Discussed upstream.
- **Ordered comparison on a non-version value (`platform_release >= "6.0"` on `6.8.0-45-generic`).** PEP 508 says to fall back to a string comparison (true here). packaging returns false for an invalid version since 22.0; uv and poetry-core compare. Long-standing upstream discussion.

- **Uppercase pre/post/dev tags are not lowercased (`1.0RC1` sorts before `1.0a1`).** `ReleaseTag.__post_init__` looks the phase up in its alias table without lowercasing it first.
- **Poetry's own constraint syntax is accepted (`~1.0`, `=1.0`, a bare `1.0`, local versions with `>=`).** `parse_constraint` parses Poetry's dependency syntax, a superset of PEP 440 specifiers.
- **`===` is not supported.** poetry-core's constraint parser has no arbitrary-equality operator.
- **An empty specifier or empty clause (`""`, `,`, a trailing comma) is rejected.** The PEP 440 grammar has no empty clause; packaging silently drops it.
- **A marker comparing a version key with an invalid version is rejected.** poetry-core raises InvalidMarkerError where packaging falls back to a string comparison or raises.
- **A marker with the string on the left (`"linux" == sys_platform`) fails to parse.** The grammar accepts it, but `_compact_markers` only handles swapped operands for `in` / `not in`.
